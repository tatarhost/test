# Архитектура HYPERREAL SHADERS v1.0

Документ описывает, из чего собран пак, в каком порядке идут проходы, какие буферы используются и
как устроены ключевые алгоритмы. Файл полезен и для отладки, и как введение для тех, кто хочет
менять пак.

## 1. Принципы

1. **Один источник истины на каждую вещь.** Форматы буферов — только `lib/buffers.glsl`, опции — только
   `lib/settings.glsl`, запись G-буфера — только `writeGBuffer()`.
2. **Пакет никогда не читает буфер, в который пишет.** Цепочка проходов строго однонаправленная, поэтому
   framebuffer feedback (частая причина чёрного экрана) невозможен по конструкции, а не «в среднем».
3. **Никакой истории кадров.** Нет TAA и temporal reprojection-накопления → нет ghosting и «шлейфов»
   при телепортации, смене измерения и переключении настроек. Всё, что могло бы требовать истории
   (SSGI, SSR, автоэкспозиция), считается пространственно.
4. **Дорогие эффекты включаются опциями,** а не «всегда включены и надеемся на GPU».
5. **Все модули — заголовки без состояния:** функции чистые, зависят только от аргументов и uniform'ов.

## 2. Порядок проходов

```
              ┌─ shadow.vsh/fsh ──────────── карта теней (shadowtex0/1)
              │
 mировой ─────┼─ gbuffers_*  ─────────────► colortex0..3  (+ colortex6 для воды/стекла)
 рендер       │
              └─ gbuffers_sky*  ───────────► colortex0..3 (небо пишется уже освещённым)

composite.fsh     читает 0,1,2,3, depthtex1     ► пишет 4 (SSGI rgb + SSAO a), 5 (SSR rgb + conf a)
composite1.fsh    читает 0,1,2,3,4,5,6, depth   ► пишет 7 (шейдинг: AO, GI, контактные тени, SSR,
                                                            вода, стекло, рука)
composite2.fsh    читает 7                      ► пишет 0 (объёмные облака поверх сцены)
composite3.fsh    читает 0, depth               ► пишет 7 (атмосферный туман, объёмный свет, god rays)
composite4.fsh    читает 7                      ► пишет 4 (bright pass, downsample 4×4)
composite5.fsh    читает 4                      ► пишет 5 (широкий гауссов bloom, 2 прохода в одном шейдере)
final.fsh         читает 7,5,4, depth/нормали   ► экран (CA → DoF → motion blur → bloom → экспозиция
                                                  → ACES → flare → грейд → виньетка → резкость → зерно
                                                  → дизеринг → sRGB)
```

`gbuffers_clouds` существует, но ванильные облака отключены (`clouds=off`), поэтому проход пустой по
смыслу: он оставлен, чтобы Iris не подставлял дефолтный шейдер, если пользователь включит ванильные
облака обратно.

`gbuffers_hand` / `gbuffers_hand_water` используют те же шейдеры, что и мир, с флагом руки в
`colortex3.a` — так рука не попадает в SSR/DoF/bloom-окклюзию.

## 3. Буферы

Полная карта — в `lib/buffers.glsl` (форматы 0..7). Кратко:

| id | формат | содержимое |
|---|---|---|
| 0 | RGBA16F | HDR-цвет сцены, A = покрытие |
| 1 | RGBA16 | нормаль (октаэдрическое кодирование) + класс материала |
| 2 | RGBA16 | sky light, block light, emissive, wetness |
| 3 | RGBA16 | roughness, metalness, subsurface, hand flag |
| 4 | RGBA16F | SSAO/SSGI → затем bright pass |
| 5 | RGBA16F | SSR → затем размытый bloom |
| 6 | RGBA16F | forward-цвет прозрачных поверхностей (вода, стекло) |
| 7 | RGBA16F | сцена после тумана и объёмного света — вход постобработки |

Почему 16F для цвета: диск солнца и светящиеся блоки имеют яркость далеко за 1.0, и именно эти
значения нужны bright pass'у. Почему 16-битные нормализованные для нормалей и параметров: 8 бит дают
полосы на больших плавно освещённых поверхностях, 32 бита — лишняя пропускная способность.

## 4. Модули `shaders/lib`

| Файл | Назначение |
|---|---|
| `settings.glsl` | все опции и engine-константы (`shadowMapResolution`, `shadowDistance`, ...) |
| `uniforms.glsl` | объявления uniform'ов и сэмплеров, ровно те, что предоставляет Iris |
| `varyings.glsl` | общие `varying` вершинного и фрагментного шейдеров |
| `attributes.glsl` | обёртки над `vaPosition`, `vaUV0`, `vaUV2`, `vaNormal`, `mc_Entity`, `at_tangent` |
| `util.glsl` | математика, хэши, шумы (`valueNoise`, `gradNoise`, `fbm`, `worley`), кодирование нормалей и классов материалов, уровни света |
| `space.glsl` | преобразования экран ↔ view ↔ world, `linearDepth`, лучи по глубине |
| `buffers.glsl` | форматы colortex, карта буферов, число буферов |
| `atmosphere.glsl` | атмосфера: оптические толщины, `atmosphereScattering`, диск солнца/луны, звёзды, млечный путь, сияние |
| `sky.glsl` | сборка неба (`renderSky`), направление и цвет солнца/луны, `dayFactor`, `netherSky` |
| `sky_fsh.glsl` | тело `gbuffers_skybasic` / `gbuffers_skytextured` (звёзды, солнце, луна, радужный градиент) |
| `clouds.glsl` | объёмные облака: coverage-карта, slab intersection, рейтрейсинг, свет в облаке, тени от облаков, отражение облачного слоя |
| `shadows.glsl` | искажение клип-пространства, PCF 1/4/9/17, PCSS, normal offset bias, `getShadowVisibility*` |
| `brdf.glsl` | GGX/Smith/Schlick, энергосберегающий диффуз, wrapped diffuse (SSS), specularDirect |
| `lighting.glsl` | сборка освещения: прямой свет + ambient + свет от блоков + свет в руке |
| `materials.glsl` | id блоков, `Material`, PBR-карты, эвристические материалы, perturbNormal, wetness |
| `vegetation.glsl` | параметры ветра и смещение вершин для растений, листвы, келпа |
| `water.glsl` | волны, нормали, поглощение, каустики |
| `water_fsh.glsl` | фрагментный шейдер воды (волны + forward-цвет в colortex6) |
| `gbuffer_out.glsl` | `writeGBuffer()` — единственное место записи G-буфера |
| `trans_out.glsl` | `writeTranslucent()` — запись forward-цвета прозрачных поверхностей |

| `composite_common.glsl` | хелперы чтения G-буфера: класс материала, мокрость, глубина, view-позиция, экранный размер текселя |
| `fog.glsl` | плотность тумана по высоте, фазовая функция, марш тумана и god rays |
| `post.glsl` | тонмаппинг, грейд, виньетка, CA, резкость, зерно, дизеринг |

## 5. Ключевые алгоритмы

### 5.1 Тени
* Карта одна (пак не может создать каскады), поэтому клип-пространство искажается монотонной
  функцией `g(r) = r·(1 + K·(1 − r))`: у камеры больше текселей, у горизонта меньше.
* Фильтрация: 1/4/9/17 выборок PCF; при включённом PCSS сначала ищутся перекрытия (blocker search)
  в регионе размером с источник света, затем по средней глубине перекрытий вычисляется размер
  полутени — это даёт «контактное уплотнение» теней, характерное для area-light.
* Смещения: комбинация slope-scaled depth bias и world-space normal offset, чтобы не было ни «акне»,
  ни отрыва тени от объекта.
* `getShadowVisibilityFast()` — дешёвый вариант (без PCSS) для облаков, воды и объёмного света.

### 5.2 SSAO и SSGI
* SSAO: 10 выборок в полусфере по спирали с поворотом на per-pixel шум, радиус ограничен по глубине
  (иначе дальние объекты дают ореолы).
* SSGI: короткие лучи по косинусному распределению, сбор цвета из `colortex0`, затухание по расстоянию.
  Это один отскок: полноценный multi-bounce GI в экранном пространстве нестабилен и шумен.

### 5.3 SSR
* Марш луча в view-пространстве по `depthtex1` с шагом, растущим по расстоянию, затем 5 итераций
  бинарного уточнения.
* Отбраковка по нормали и по «выходу за экран», веса по краям экрана (fade), при промахе — фолбэк на
  небо/облака.
* `REFLECTION_ROUGH`: луч джиттерится по GGX-распределению, это даёт размытые отражения на матовых
  материалах.

### 5.4 Вода
* Пять направленных синусоид: высота и аналитические производные считаются из одной суммы, поэтому
  нормаль всегда согласована с геометрией.
* Смещение только по Y и только от мировых XZ: соседние вершины одного столбца воды смещаются
  одинаково → поверхность остаётся герметичной, без щелей между блоками.
* Поглощение: `exp(-absorption · pathLength)` по реальной толще воды между камерой и дном, плюс
  рассеяние — цвет получается физически (зелёная вода на глубине, голубая на мелководье).
* Каустики: анимированный Worley-паттерн, маскированный толщиной воды и глубиной.

### 5.5 Атмосфера
* Однократное рассеяние: Рэлей + Ми + озон, интегрирование по 8–24 шагам вдоль луча зрения с
  оптической толщей до солнца. Число шагов = `ATMOSPHERE_QUALITY`.
* Диски светил: аналитическое пересечение сферы с учётом лимба; у луны — фаза из `moonPhase`.
* Звёзды: процедурное поле по направлению, мерцание по времени, млечный путь как полоса fbm.
* Сияние: две полосы `aurora` с шумом и затуханием к горизонту.

### 5.6 Облака
* Slab intersection: пересечение луча с плоскостями base/top, затем фронт-то-бэк марш.
* Плотность = coverage (2D fbm, анимированный ветром) × вертикальный профиль × 3D fbm (2–3 октавы
  по `CLOUD_QUALITY`).
* Освещение сэмпла: Beer по направлению к солнцу + «powder» (тёмные края) + ambient сверху; это
  дешёвая аппроксимация многократного рассеяния.
* Тени от облаков: та же coverage-карта на плоскости облаков, сэмплируется в точку теневой карты.
* Отражение облачного слоя (`cloudLayerReflection`) используется водой и стеклом вместо дорогого
  марша.

### 5.7 Постобработка
* Bloom: bright pass с мягким коленом + downsample 4×4 в `composite4`, широкое гауссово размытие в
  `composite5`, композит в `final`.
* Автоэкспозиция: средняя логарифмическая яркость по сетке 5×5 с весами, clamp 0.35–3.2. Без истории
  → нет «дыхания» экспозиции после телепорта.
* DoF: 12 тапов по golden-angle спирали, радиус из CoC, защита от bleed (сэмплы сильно ближе к камере
  игнорируются).
* Motion blur: скорость по репроекции `gbufferPreviousModelView/Projection`, 8 тапов, ограничение
  длины вектора.
* Тонмаппинг: ACES (аппроксимация Hill), Reinhard, Uchimura; грейд, виньетка, CA, резкость, зерно,
  дизеринг, sRGB — в этом порядке.

## 6. Отсутствие чёрного экрана при смене настроек

* Форматы буферов не зависят от опций: они всегда одни и те же, поэтому выключение опции не меняет
  layout и не требует пересоздания буферов.
* Ни один шейдер не «оптимизируется в пустоту»: при выключенной опции соответствующая функция
  возвращает нейтральное значение (0 или исходный цвет), а не пропадает.
* Буферы очищаются каждый кадр, поэтому после смены измерения или профиля в кадре нет старых данных.
* Отладочные виды читают уже посчитанные буферы, а не меняют их содержимое.

## 7. Как добавить эффект

1. Опция — в `lib/settings.glsl` (`#define`/`const` с комментарием-значениями).
2. Экран/слайдер — в `shaders.properties`, перевод — в `lang/*.lang`.
3. Функция — в подходящий `lib/`-модуль (с комментарием, если алгоритм нетривиален).
4. Вызов — в проход, который **не** пишет буфер, читаемый этим эффектом (см. таблицу §2).
5. Если нужен новый буфер — добавить формат в `lib/buffers.glsl` и обновить таблицу.
6. `python3 tools/check_pack.py && python3 tools/compile_shaders.py`.
